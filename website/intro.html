What is Skein

A coding agent that lives in your terminal.

In one sentence: you describe a change in plain language, Skein finds the relevant code with its own local index, edits with your permission, runs your tests, and only reports success when the tests prove it.

1

You ask

skein "fix the flaky webhook retry test" — plain language, or pin files with @path. Works interactively or as a one-shot command.

2

It works transparently

Every file read, patch, and command shows up in a live timeline. Writes need your approval and get automatic pre-write checkpoints you can restore.

3

You get proof

The run ends with a completion status backed by real test and typecheck results — never just the model's word. Sessions persist, so you can resume or audit anything later.

Why Skein

Agents guess. Skein grounds, gates, and proves.

Three design commitments separate Skein from a chat loop with shell access.

⌁

Context first

A local BM25 + path + symbol + import-graph index ranks real spans with scores, line ranges, and content hashes. No retrieval service, no embeddings bill — skein search works offline.

▣

Evidence-gated completion

“Done” is a status the model cannot grant itself. Only current, successful test / typecheck / build / diff-check tool runs after the last mutation yield verified — prose never does.

◈

Trust as architecture

Independent read/write/shell/git/network permissions, workspace-root enforcement, pre-write checkpoints, and untrusted-by-default project config. Cloned repos can’t execute anything by merely being cloned.

Three-minute tour

Install. Connect. Run. Verify.

Everything below is the real CLI surface — the same commands the test suite and man page are generated from.

1 · Install
# Node.js 22.16 or newer
npm install -g @skein-code/cli
skein --version
man skein          # generated from the CLI itself, 21 subcommands
2 · Connect
export TEAM_RELAY_API_KEY=…   # Skein stores the NAME, never the value

skein agents setup --yes \
  --name team-relay \
  --provider compatible \
  --protocol openai-responses \
  --base-url https://relay.example/v1 \
  --api-key-env TEAM_RELAY_API_KEY \
  --model provider/coding-model
3 · Run
skein                          # composer-first interactive workspace
skein "fix the failing test"   # one instruction, live tool timeline

# CI-grade headless: published JSON schema + stable exit codes
skein -p "summarize the failing tests" --output-format json
# 0 = verified · 1 = unverified · … · 9 = needs review
4 · Recover
skein session list             # durable, resumable, forkable sessions
skein checkpoint list          # every mutation has a pre-write snapshot
skein checkpoint restore <s> <c>
skein /recover                 # in-TUI: retry, diff, audit, rollback
What’s inside

A full workshop, not a wrapper.

Twenty-one subcommands, grouped the way you actually work.

☰

Local retrieval engine

Grounded spans with score provenance (bm25 · path · symbol · graph · recency), incremental refresh of only changed paths, multilingual recall benchmarks with checked-in quality gates.

⇄

Model-agnostic relays

OpenAI Responses, Chat Completions, and Anthropic Messages — protocol always explicit, never guessed from a URL. No cross-protocol retries billing you twice.

⚑

Multi-model teams

Route reviewer, architect, and tester roles to different providers. Team Runs persist content-addressed reports with reviewer verdicts bound to exact patch SHA-256.

✂

Reuse over duplication

A TS/JS clone detector blocks completion on exact Type-1/2 duplicates — the agent must reuse your code, not paste a second copy of it.

◔

Token economy

Adaptive retrieval budgets, context epochs with content-free handoffs, compaction that only runs when three predicted reuses show positive net savings.

✳

Extensible, but gated

MCP with fingerprint-bound trust and lazy activation, workspace Skills that fail closed on content drift, typed workflows, durable background jobs.

Invariants

Rules the model can’t vote on.

These hold across every provider, mode, and flag — including --yes.

1

Deterministic truth wins

Passing receipts beat conflicting model judgment; failing oracles cannot be overridden by any reviewer, human-persuasive prose included.

2

Content-free telemetry

Receipts and registries keep hashes, counts, and bounded aggregates only — no prompts, no source text, no command arguments, no credentials.

3

Live-human gates stay human

Git push, publish, destructive commands, writer integration: no flag, config rule, or model review can stand in for a person saying yes.

4

Cloned code has no authority

Project-local config is untrusted by default. Hooks, endpoints, and verification commands activate only after explicit --trust-project-config.

FAQ

Fair questions.

Does Skein send my code to a retrieval service?
No. The index is built and stored locally at .skein/index.json. Retrieval, ranking, and packing run on your machine; only the context you approve for a model turn goes to the relay you configured.
What happens to my API keys?
Skein saves the environment-variable name, never the value. Diagnostics redact secrets, URLs, and query strings; receipts are content-free by design.
Can I use it in CI?
Yes — --print --output-format json follows a published schema with a stable exit-code contract (0 verified … 9 needs review), so pipelines gate on results without parsing prose.
Which models does it work with?
Any OpenAI-Responses, OpenAI-Chat, or Anthropic-Messages compatible endpoint. You choose the protocol explicitly per connection; Skein never probes or guesses at your expense.
Is it actually tested?
Every release passes typecheck, 770+ tests, real-PTY terminal regressions across widths 20–120 (including screen readers and TERM=dumb), benchmark quality gates, and a byte-verified npm artifact.
